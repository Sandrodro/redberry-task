# Kino XII

Cinema booking frontend for the Redberry Bootcamp XII task. Users browse films, filter sessions, pick seats, hold them, and pay for tickets.

- Live demo: <https://redberry-task-blond.vercel.app/>
- API docs: <https://api.kinoxii.redberryinternship.ge/docs>

## Getting started

```bash
pnpm install
cp .env.example .env   # sets VITE_API_URL
pnpm dev
```

| Script         | What it does                   |
| -------------- | ------------------------------ |
| `pnpm dev`     | Starts the dev server          |
| `pnpm build`   | Runs `tsc -b` and `vite build` |
| `pnpm lint`    | Runs oxlint                    |
| `pnpm format`  | Runs Prettier on `src/`        |
| `pnpm preview` | Serves the production build    |

`src/routeTree.gen.ts` is generated by the router plugin. On a fresh clone, run `pnpm dev` once before `pnpm build`.

GitHub Actions (`.github/workflows/ci.yml`) runs lint and build on every pull request and push to `main`. Vercel hosts the app. `vercel.json` rewrites every path to `index.html` for client-side routing.

## Tech stack

| Area          | Choice                                                                      |
| ------------- | --------------------------------------------------------------------------- |
| UI            | React 19, TypeScript, Vite                                                  |
| Styling       | Tailwind v4 with theme tokens in `src/index.css`, Archivo font (fontsource) |
| Routing       | TanStack Router, file-based, automatic code splitting                       |
| Server state  | TanStack Query                                                              |
| Forms         | TanStack Form, Zod schemas                                                  |
| UI primitives | Radix UI (dropdown menu, tabs, tooltip), Embla Carousel                     |
| Tooling       | pnpm, oxlint, Prettier, `vite-plugin-svgr` (SVG icons as components)        |

## Project structure

```
src/
  api/          fetch client, endpoints, query keys, types, one hook per query or mutation
  components/
    core/       base UI (Button, Input, Modal, Typography, ErrorState, EmptyState, ...)
    layout/     app shell: header, footer, profile menu
    pages/      one folder per page, with the components only that page uses
    booking/    booking modal and its steps
    auth/       login, sign up, avatar upload
    search/     header search
    session/    session UI shared by the sessions and movie pages
  hooks/        app hooks (useAuth, useDebouncedValue, usePrefetchTickets, ...)
  providers/    context providers mounted in the root route
  routes/       route files only
  utils/        schemas/ (Zod), formatters/, form/, and generic helpers
```

Rules that keep it consistent:

- A route file only calls `createFileRoute`, sets loaders, and renders a page component. It has no page logic.
- A component used by one page lives in that page's folder. When a second page needs it, it moves to `src/components/`.
- Helpers do not live in component files. They go in a `utils.ts` next to the feature, or in `src/utils/<kind>/` when shared.
- All text uses `Typography`. All colors come from theme tokens. No hardcoded hex values.
