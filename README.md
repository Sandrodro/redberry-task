# Kino XII

Cinema booking frontend for the Redberry Bootcamp XII task. Users browse films, filter sessions, pick seats, hold them, and pay for tickets.

- Live demo: <https://redberry-task-blond.vercel.app/>
- API docs: <https://api.kinoxii.redberryinternship.ge/docs>

## Getting started

```bash
pnpm install
cp .env.example .env   # sets VITE_API_URL
pnpm dev
```

| Script         | What it does                   |
| -------------- | ------------------------------ |
| `pnpm dev`     | Starts the dev server          |
| `pnpm build`   | Runs `tsc -b` and `vite build` |
| `pnpm lint`    | Runs oxlint                    |
| `pnpm format`  | Runs Prettier on `src/`        |
| `pnpm preview` | Serves the production build    |

`src/routeTree.gen.ts` is generated by the router plugin. On a fresh clone, run `pnpm dev` once before `pnpm build`.

GitHub Actions (`.github/workflows/ci.yml`) runs lint and build on every pull request and push to `main`. Vercel hosts the app. `vercel.json` rewrites every path to `index.html` for client-side routing.

## Project structure

```
src/
  api/          fetch client, endpoints, query keys, types, one hook per query or mutation
  components/
    core/       base UI (Button, Input, Modal, Typography, ErrorState, EmptyState, ...)
    layout/     app shell: header, footer, profile menu
    pages/      one folder per page, with the components only that page uses
    booking/    booking modal and its steps
    auth/       login, sign up, avatar upload
    search/     header search
    session/    session UI shared by the sessions and movie pages
  hooks/        app hooks (useAuth, useDebouncedValue, usePrefetchTickets, ...)
  providers/    context providers mounted in the root route
  routes/       route files only
  utils/        schemas/ (Zod), formatters/, form/, and generic helpers
```

Rules that keep it consistent:

- A route file only calls `createFileRoute`, sets loaders, and renders a page component. It has no page logic.
- A component used by one page lives in that page's folder. When a second page needs it, it moves to `src/components/`.
- Helpers do not live in component files. They go in a `utils.ts` next to the feature, or in `src/utils/<kind>/` when shared.
- All text uses `Typography`. All colors come from theme tokens. No hardcoded hex values.

## Architecture decisions

**Data layer.** Each query is a hook named `use{Thing}Data` in `src/api/queries/<resource>/`. Query keys are plain `as const` objects in `src/api/queryKeys.ts`, and mutations invalidate with `xKeys.all`. A query that waits for an input (like `useHoldData`) uses `skipToken` as its `queryFn`. After a mutation, the UI shows what the server returned or refetched, not the submitted values. Paths come from the `Endpoint` const object. Values the API owns (venues, formats, ticket ratios, seat cap, hold minutes) are read from `/filter-options`, never hardcoded.

**Error handling.** `src/api/client.ts` turns every failure into one `ApiError`, so `error.message` is always safe to show.

- A network failure or a `5xx` gets a generic message. Server text is never shown.
- `422` with `errors` maps to form fields (`setServerErrors`). A field clears its server message when the user enters a valid value.
- `422` with only `message` is a booking rule. The message is shown as a notice.
- `409` means seats were lost. The `contested` codes mark those seats in the seat map.
- Queries retry up to 3 times, except on `4xx` errors, which do not change on retry.
- Every list has three states: loading (skeleton or spinner), error (`ErrorState` with a retry button, disabled while it retries), and empty (`EmptyState`). An error is never shown as an empty list.
- Route errors go to `RouteError`, set as the router default.

**Session expiry (`401`).** Components never handle `401`. The client calls a handler registered by `AuthModalProvider`, which opens the login modal. Requests that fail together share one login. After a successful login, each request is sent again with the new token. If the user cancels, the request fails. Auth endpoints are excluded, because their `401` means a wrong password or a stale token.

**Auth and protected routes.** Routes in `src/routes/_protected/` need a logged in user. A guest sees the login modal on the same URL and goes home if they close it. `useAuthModal().openLogin({ onSuccess, onCancel })` lets any action resume after login. For example, clicking a session as a guest opens the login modal and then opens the booking modal.

**URL as state.** The sessions page keeps its filters, date, sort, and page in the URL (`?venue=galleria,batumi&date=2026-11-14&sort=price_asc`). A Zod schema validates the search params, and a bad value falls back to "not set". Values that `/filter-options` does not know are dropped before the request, because the API rejects the whole request with `422` for an unknown value. The links can be shared and the back button works.

**Forms.** Each form has a Zod schema in `src/utils/schemas/`, passed to TanStack Form as `onMount` and `onChange` validators. A field error shows only after the field is blurred. Server field errors are set in the form's error map, so they use the same field error display.

**Booking flow.** The steps run through a reducer (`bookingReducer.ts`). The hold ID is saved in localStorage. If the user reloads or reopens the modal, the booking resumes at checkout when the hold is still live, and the stale ID is removed when it is not. The hold countdown ticks against the absolute expiry time, so a background tab does not drift.

## Extra polish

- **Debouncing.** The header search and the sessions filters use `useDebouncedValue` (300 ms). Quick clicks on several filters send one request. The previous results stay on screen, dimmed, until the new ones arrive (`keepPreviousData`).
- **Route loaders.** The home page waits for the featured banner. The movie page waits for the movie and its first day of sessions. The sessions page waits for the filter options. These pages open with their key data already loaded.
- **Hover prefetch.** Hovering a date on the movie page loads that day's sessions. Hovering a link to My Tickets loads both ticket tabs (`usePrefetchTickets`).
- **Lazy loading.** The booking modal (seat map and checkout) loads on first open. The profile menu, which pulls in Radix, loads only for a logged in user. A placeholder holds its space, so the header does not jump.
- **Recently viewed.** The home page lists the last 5 films the user opened, kept in localStorage and validated with Zod.
- **Sessions page behavior.** When a filter changes, the page scrolls the results back into view while the filter panel stays sticky. If the user deselects a venue, formats that no venue offers are removed from the URL.
- **Carousels.** The hero carousel autoplays and pauses on hover. Sliders respond to wheel and trackpad gestures.
- **Access rules.** Sessions that are too old for the user's age are disabled, with the reason on the movie page. Ended sessions show a tooltip.
