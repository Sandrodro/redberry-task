# Kino XII

- Live demo: <https://redberry-task-blond.vercel.app/>

## Getting started

```bash
pnpm install
cp .env.example .env   # sets VITE_API_URL
pnpm dev
```

| Script         | What it does                   |
| -------------- | ------------------------------ |
| `pnpm dev`     | Starts the dev server          |
| `pnpm build`   | Runs `tsc -b` and `vite build` |
| `pnpm lint`    | Runs oxlint                    |
| `pnpm format`  | Runs Prettier on `src/`        |
| `pnpm preview` | Serves the production build    |

`src/routeTree.gen.ts` is generated by the router plugin. On a fresh clone, run `pnpm dev` once before `pnpm build`.

GitHub Actions (`.github/workflows/ci.yml`) runs lint and build on every pull request and push to `main`. Vercel hosts the app. `vercel.json` rewrites every path to `index.html` for client-side routing.

## Things i did that were not specified in the brief

- **Ended sessions are disabled.** A session has ended when its start time plus the film's runtime is in the past (`src/utils/hasSessionEnded.ts`). An ended session card cannot be clicked, and a tooltip on hover says "The screening has already ended". On the movie detail page, the date strip disables a day that is not in the movie's `availableDates`. If today is disabled because no session is left to book, a tooltip on hover says "All sessions have ended for this day".
- **Select and calendar designs.** The brief did not include designs for the select dropdowns (sort, venue) or the calendar (date picker), so I made my own, built on Radix and shadcn and styled with the app's theme tokens.

## Project structure

```
src/
  api/          fetch client, endpoints, query keys, types, one hook per query or mutation
  components/
    core/       base UI (Button, Input, Modal, Typography, ErrorState, EmptyState, ...)
    layout/     app shell: header, footer, profile menu
    pages/      one folder per page, with the components only that page uses
    booking/    booking modal and its steps
    auth/       login, sign up, avatar upload
    search/     header search
    session/    session UI shared by the sessions and movie pages
  hooks/        app hooks (useAuth, useDebouncedValue, usePrefetchTickets, ...)
  providers/    context providers mounted in the root route
  routes/       route files only
  utils/        schemas/ (Zod), formatters/, form/, and generic helpers
```

## Code organization

- **Routes** in `src/routes/` only declare the route and render a page component. Routes that need a logged in user go in `src/routes/_protected/`.
- **Pages** live in `src/components/pages/{name}/`. `{Name}Page` (`HomePage`, `MoviePage`, `SessionsPage`, `ProfilePage`) is the whole page. The components only that page uses sit next to it. When a second page needs one, it moves up to `src/components/`.
- **Feature folders** (`booking/`, `auth/`, `search/`, `session/`) hold components that more than one page uses.
- **Core components** in `src/components/core/` are the base UI. Radix primitives are wrapped there (`DropdownMenu`, `Popover`, `Select`, `Tooltip`). All text goes through `Typography`, and colors come from the theme tokens in `src/index.css`.
- **API**: each query is one hook in its own file, named `use{Thing}Data` (`useFeaturedMoviesData`). Mutations are verb hooks (`useLogin`, `useCreateHold`) that invalidate what they change. Paths come from `Endpoint` and query keys from `queryKeys.ts`.
- **Forms**: each form has a Zod schema in `src/utils/schemas/`. Server field errors (`422`) go into the form fields.
- **Helpers**: a helper used by one folder stays in a `utils.ts` or `helpers.ts` next to its components. A shared helper goes in `src/utils/`, in a subfolder for its kind (`formatters/`, `schemas/`, `form/`).
- **Lists** always have loading, error (with retry), and empty states.
